# change-impact-{id}.xlsx — Artifact Schema (EN)

This file defines the structure, column layout, formulas, and data examples
for the `change-impact-{id}.xlsx` artifact generated by the `generate-change-impact` skill.

---

## File Metadata

| Field | Value |
|-------|-------|
| File name | `change-impact-{id}.xlsx` (example: `change-impact-CR-001.xlsx`) |
| Save path | `{project}/04-development/` |
| Sheets | 2 — Summary, Impact Detail |
| Version | 1.0 |

---

## Sheet 1 — Summary

### Header Block (rows 1–5)

| Cell | Content |
|------|---------|
| A1 | "Project:" |
| B1 | `{project_name}` — from project-charter.md or from PM |
| A2 | "PM:" |
| B2 | `{pm_name}` |
| A3 | "Phase:" |
| B3 | "4 — Development" |
| A4 | "Assessment date:" |
| B4 | `{YYYY-MM-DD}` |
| A5 | "Version:" |
| B5 | "1.0" |

---

### Change Request Block (rows 8–15)

| Field | Content |
|-------|---------|
| Request ID | `{CR-001}` |
| Title | `{short_change_title}` |
| Category | `{scope / budget / timeline / resource}` |
| Secondary categories | `{if applicable, otherwise "—"}` |
| Requester | `{name_or_role}` |
| Request date | `{YYYY-MM-DD}` |
| Description | `{1–3 sentences: what exactly is changing}` |
| Rationale | `{1–2 sentences: why the change is needed}` |

> **Agent instruction:** fill all fields based on PM input from Step 2.
> If data is not provided — leave `"not specified"`.
> Determine category automatically from the description; list secondary categories
> only if the change clearly affects multiple dimensions.

---

### Impact Assessment Block (rows 18–26)

| Dimension | Metric | Value |
|-----------|--------|-------|
| Timeline | Final deadline shift | `{+X working days / "no impact"}` |
| Timeline | Affected tasks | `{N tasks / "no impact"}` |
| Timeline | Critical path | `{"shifts" / "does not shift"}` |
| Budget | Delta (absolute) | `{+X / "0" / "to be confirmed"}` |
| Budget | Delta (%) | `{+X% / "0%" / "to be confirmed"}` |
| Resources | Changes required | `{"yes" / "no"}` |
| Resources | Description | `{if "yes" — what / "—"}` |
| **Impact level** | | `{Low / Medium / High}` |

**Colour coding for impact level:**
- Low: green fill (#C6EFCE)
- Medium: yellow fill (#FFEB9C)
- High: red fill (#FFC7CE)

> **Agent instruction:** determine impact level using the matrix from skill-spec-ru.md
> (Step 4.4). Bold the "Impact level" row + apply colour fill as above.
> Document data sources in Sheet 2 (Impact Detail).

---

### Agent Recommendation Block (rows 29–31)

| Field | Content |
|-------|---------|
| Agent assessment | `{1–2 sentences: concise summary of impact level and key risks}` |
| Key risk (if approved) | `{main risk of accepting the change, 1 sentence}` |
| Key risk (if rejected) | `{risk of rejecting the change, 1 sentence or "—"}` |

> **Agent instruction:** write an objective assessment without recommending to "approve/reject".
> Example: "The change adds 2 new modules, shifts Sprint 3 deadline by 8 working days
> and increases budget by 12%. Main risk — backend team overload."
> DO NOT write "I recommend approving/rejecting" — that is the PM's decision.

|-------|---------|

| Decision date | _(PM fills in)_ |

---

### Assumptions Block (rows 42–48)

| # | Assumption |
|---|------------|
| 1 | Impact assessment is based on project-plan.md and project-budget.xlsx as of the assessment date |
| 2 | If project files were not loaded — assessment is based on PM description and is preliminary |
| 3 | Impact levels: Low (shift ≤ 5 days, budget delta ≤ 5%), Medium (6–15 days / 6–15%), High (>15 days / >15%) |
| 4 | Timeline shifts are in working days (5 days per week) |
| 5 | Financial figures are in project currency |
| 6 | `{additional_agent_notes}` |

| B1 | `{project_name}` |
| A2 | "CR ID:" |

---

### Block 1 — Timeline Impact (row 6 onwards)

Table of affected tasks/milestones:

| Task / Milestone | Current deadline | New deadline | Shift (working days) | Critical path | Comment |
|-----------------|-----------------|-------------|---------------------|--------------|---------|
| `{task_name}` | `{YYYY-MM-DD}` | `{YYYY-MM-DD}` | `{+N}` | `{yes / no}` | `{rationale}` |
| ... | | | | | |
| **Total: final deadline shift** | | | `=SUM(shifts_on_critical_path)` | | |

> **Agent instruction:** add a row for each affected task from project-plan.md.
> If the file is not loaded — list tasks based on the change description with note "estimate".
> If the change does not affect the timeline — write "Change does not affect the timeline".

**Formatting:**
- Critical path tasks: bold
- Total row: yellow fill (#FFF2CC), bold
- Positive shift (delay): red text colour
- Zero shift: standard colour

---

### Block 2 — Budget Impact (after timeline table, 3 blank rows)

Table of affected budget items:

| Budget item | Approved amount | New amount | Delta | Delta (%) | Comment |
|------------|----------------|-----------|-------|-----------|---------|
| `{item_name}` | `{amount}` | `{new_amount}` | `=New-Approved` | `=Delta/Approved*100` | `{rationale}` |
| ... | | | | | |
| **Total** | `=SUM(approved)` | `=SUM(new)` | `=SUM(deltas)` | `=Total_delta/Total_approved*100` | |

> **Agent instruction:** add rows for affected budget items from project-budget.xlsx.
> If the file is not loaded — list items based on the description with note "estimate" and value "to be confirmed".
> If the change does not affect budget — write "Change does not affect the budget".

**Formatting:**
- Currency: number format with thousands separator, 2 decimal places
- Total row: yellow fill (#FFF2CC), bold
- Positive delta (overrun): red text colour (#9C0006)

---

### Block 3 — Resource Impact (after budget table, 3 blank rows)

| Resource / Role | Current allocation | Required allocation | Delta | Comment |
|----------------|-------------------|--------------------|---------  |---------|
| `{role_or_name}` | `{X%_or_X_days}` | `{Y%_or_Y_days}` | `{+Z}` | `{rationale}` |

> **Agent instruction:** fill only if the change requires resource changes.
> If resources are not affected — write "Change does not require resource adjustments".

---

### Block 4 — Dependencies & Side Effects (after resource table, 3 blank rows)

| Affected element | Type | Description of effect |
|-----------------|------|----------------------|
| `{milestone / risk / comm-plan item}` | `{milestone / risk / comm-plan / other}` | `{1–2 sentences}` |

> **Agent instruction:** list side effects — shifted milestones, heightened risks,
> comm-plan adjustments. If no side effects — write "No side effects identified".

## Formatting Rules

| Element | Style |
|---------|-------|
| Header blocks | Bold, grey fill (#D9D9D9) |
| Data rows | Alternating white / light blue (#EBF3FB) |
| Total rows | Yellow fill (#FFF2CC), bold |
| Impact level Low | Green fill (#C6EFCE) |
| Impact level Medium | Yellow fill (#FFEB9C) |
| Impact level High | Red fill (#FFC7CE) |
| Positive delta (delay/overrun) | Red text (#9C0006) |
| Critical path | Bold |
| Section headers | Bold, uppercase |
| Column widths (Sheet 1) | Field: 28; Value: 48 |
| Column widths (Sheet 2, timeline) | Task: 30; Dates: 14; Shift: 10; Crit.path: 12; Comment: 40 |
| Column widths (Sheet 2, budget) | Item: 30; Amounts: 16; Delta: 12; %: 10; Comment: 40 |
| Frozen rows | Row 1 on each sheet |
